# Fable Mode RAID review — 2026-09-15

## Scope and approach

Reviewed the current uncommitted revision of the core skill, its four guides,
README, project knowledge, installers, and distribution archive. This review
builds on the earlier model-agnostic rewrite; it does not attribute those earlier
changes to this pass.

The audit combined independent textual reviews, temporary installer reproductions,
and executable package checks. The review considered risks, assumptions, issues,
and dependencies. Fixes below address observed failures or specific instruction
wording; hypothetical concerns are not presented as proven defects.

## Issues and dispositions

| Finding | Evidence | Disposition |
|---|---|---|
| Missing installer argument created an unintended destination. | `--skills-dir --force` and `--skills-dir --help` succeeded and created directories named after the option under the working directory. | Shell parser rejects recognized option tokens where a value is required. A literal path such as `./--force` remains valid. |
| A forced update could fail after overwriting part of an installation. | An old `SKILL.md` plus a regular file named `references` caused copying to overwrite the skill and then fail. | Both installers preflight overlapping file/directory types. Shell regression tests assert the destination stays unchanged on these conflicts. Later I/O failures are still possible. |
| The maintenance reference was routed into every edit. | The core said to read the guide “when making changes,” including a cosmetic typo correction, despite its narrower purpose. | Routing now depends on documented behavior, relevant code checks, or a requested health review. Extra overhead was inferred from the wording, not measured across models. |
| Distribution validation depended on manually repeated commands. | Source/ZIP parity and nested references had no checked-in build/check command or tests. | Added a standard-library package checker/builder and regression tests; README and the delivery knowledge note link the commands. |

No material contradiction was found in the workflow, refuter, or knowledge rules
during textual review. That is a bounded review outcome, not proof that every
model will follow them correctly.

## Observed verification

- All 18 repository regression tests passed: eight installer cases and ten
  packaging cases. The eight installer cases also passed under `dash`.
- Source/ZIP membership and byte parity, inline local link checks, the skill
  frontmatter validator, shell syntax, and Git whitespace checks passed.
- A typo-fix trial changed only the requested spelling and used direct inspection.
  It loaded no additional skill references during the trial.
- An assigned-refuter trial examined a correct distinct-string function. Seven
  targeted cases passed across 14 invocations, and the reviewer reported no
  supported defect while limiting its conclusion to those checks.

The two behavioral trials reused the reviewer conversation, which had already
contained the references. They are follow-up smoke tests, not blind evaluations
of discovery behavior or comparisons across model providers.

## Risks and assumptions

- Host and model behavior vary. The skill assumes the host can load its text;
  references require file access or inclusion in the prompt. Model-agnostic
  instructions do not establish equivalent behavior across providers.
- Knowledge is useful only when retrieved and checked against applicable sources.
  A recent note, a passing narrow check, or reviewer agreement cannot certify an
  entire system. The current guides state these limits explicitly.
- Parallel workers can discover shared documentation or knowledge writes during
  otherwise separate tasks. The workflow guide's shared-state restriction still
  applies. No lost-update failure was demonstrated in this audit.
- An assigned refuter could over-delegate under a permissive host. Existing
  “adds value,” bounded-review, and direct-inspection guidance constrain this;
  recursive delegation was not demonstrated here.

## Dependencies and verification limits

The skill itself is Markdown and has no provider API dependency. Repository
packaging and regression checks use Python 3.9+ and the standard library; shell
installer tests require a POSIX shell. No service, scheduler, or live installation
is needed to run them.

PowerShell changes were inspected but not executed because no runtime was
available. Hosted activation and comparative model performance were not tested.
The package checker covers inline local file/directory targets, not a complete
Markdown grammar, external URLs, or anchors. Source/ZIP checks validate delivered
files, not the correctness of the instructions.

## Reproduce the repository checks

```sh
python3 scripts/package_skill.py --check
python3 -m unittest discover -s tests -v
```

Rebuild with `python3 scripts/package_skill.py --build` after skill-source changes.
The regression suite includes read-only package checks, rejected invalid builds,
archive drift, duplicate/unsafe members, missing links, missing installer values,
forced-update structural conflicts, rebuilding a missing linked archive, and
preserving the previous ZIP when a proposed build is invalid. All installation
fixtures live in temporary directories.
